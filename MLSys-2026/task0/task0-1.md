\##### 0.1Benchmark基础

Latency，延迟，即一次操作从发出到完成的时间。关心 "单次有多快"

Throughput，吞吐量，单位时间内完成的工作量。关心 "整体有多快"

Bandwidth，带宽，单位时间内能传输的数据量，即传输能力的上限

FLOPs（s = operations，复数）：浮点运算次数，是一个 "量"。比如 `n×n` 矩阵乘法 ≈ 2n³ 次 FLOPs。用来描述计算量；

FLOPS（s = per second）：每秒浮点运算次数，是一个 "率"。单位是 FLOPS、GFLOPS、TFLOPS。用来描述算力速度

P50 / P95 / P99 ：把 N 次测量结果从小到大排序，Px = 有 x% 的数据不超过这个值

\---

Warmup 是正式计时前先跑几轮预热，因为GPU 首次真正使用时有一大堆一次性开销，比如加载驱动、创建 CUDA context、显存分配等，这些开销只在第一次发生，若不预热就会被算进测量结果，污染数据，所以标准流程是：warmup 几轮 → 再正式计时

\---

不能只运行一次的原因是单次测量混入了大量不可控噪声，如CPU 频率波动、GPU 时钟未稳定、系统中断、后台进程等，多次运行 + 统计（分位数 / 均值 / 方差）才能得到稳定、可复现的估计

\---

GPU异步执行原因：

CPU GPU是两个独立的硬件，可以同时分别进行计算，提高时间利用率，提高整体吞吐量

主机到GPU显存的数据拷贝很慢，在异步模式下，当GPU在进行上一批数据的计算的时候，CPU可以把下一批数据传到显存，隐藏传输延迟

\---

torch.cuda.synchronize () 的作用是阻塞 CPU，等待当前设备上所有已提交的 CUDA 操作全部执行完毕，GPU完成之后，CPU才继续执行后面的代码，是PyTorch在python侧的接口，可以用来进行计时、调试GPU报错等

\---

UDA Event 和 Python Time的区别

CUDA Event 是把计时标记放到GPU任务流里面，读取GPU硬件时钟，测GPU真正执行耗时；Python Timer是CPU上的时钟，测CPU墙上时间，受CPU-GPU异步影响，直接测GPU算子会不准
